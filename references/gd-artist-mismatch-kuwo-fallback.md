# GD 搜索误命中错误歌手时的 Kuwo 强制回退

适用场景：用户明确指定歌手，但 `music-fast-download.py` 即使带上 `"歌名" "歌手"` 参数，GD API / 网易搜索结果仍持续命中错误版本。

## 典型信号

- 搜索结果标题匹配，但歌手不匹配用户指定歌手
- 连续两次重试仍落到同一错误版本
- GD API `netease` 结果列表中根本没有目标歌手，只出现翻唱/改编/短版/DJ 版

示例：`红尘客栈 周杰伦`
- `netease` / GD 结果持续命中 `刘好听 - 红尘客栈 剑出鞘恩怨了谁笑`
- `kuwo` 结果可直接返回 `周杰伦 - 红尘客栈`

## 处理步骤

1. 先按主流程执行 `music-fast-download.py "歌名" "歌手"`。
2. 若返回歌手与用户指定不一致，不要把结果当成功；先判定为误命中。
3. 立即删除误下的音频和 `.lrc`，避免错误版本残留在 NAS 媒体库。
4. 改用旧流程强制指定 Kuwo：
   ```bash
   python3 $HOME/.openclaw/skills/media/auto-music-download/scripts/music-manager.py "歌名" "歌手" --source kuwo --quality 999
   ```
5. 以脚本输出中的 `🎶 选择：歌曲 - 歌手` 作为最小正确性确认；若这里仍非目标歌手，继续换源，不要停在错误版本。
6. 下载完成后，最少检查 NAS 目录里只保留正确版本对应的 `.flac` / `.lrc`。

## 为什么这样做

`music-fast-download.py` 当前只走 GD API + `netease`，当目标曲在该源搜索结果里缺失时，会稳定回落到错误但高相关的翻唱版本。此时继续重试同一路径没有意义，应该切到可返回正确主唱结果的 `kuwo`。

## 经验边界

- 这不是“歌名模糊就一律用 Kuwo”；只有在“用户已指定歌手、GD/netease 连续误命中、且 Kuwo 可返回目标歌手”时才切。
- 修复重点是“删除错误文件 + 强制正确来源”，不是只口头说明命中了错误版本。
